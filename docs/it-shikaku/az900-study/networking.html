5. ネットワーキングサービス(VNet・NSG・VPN・負荷分散)

ネットワーク問題の「型」は、まず「何と何を繋ぐ/制御する話か」(同じVNet内?VNet同士?オンプレ?リージョンをまたぐ?)を特定してから、道具を選ぶことです。

基本

  • 仮想ネットワーク(VNet): Azure上の自分専用のプライベートな道路網。サブネットに区切る
  • VNetピアリング: 同一リージョン内のVNet同士を接続(Microsoftのバックボーン経由、高速)
  • グローバルVNetピアリング: 異なるリージョン間のVNet接続。「リージョン間」なら「グローバル」が付く方

オンプレミスとの接続

サービス一言ポイント
VPN Gatewayインターネット越しに暗号化トンネルでオンプレとVNetを接続サイト間(S2S)、ポイント対サイト(P2S)
ローカルネットワークゲートウェイオンプレ側のVPN機器を表すAzure上のオブジェクトVPN Gatewayとセットで使う
ExpressRoute専用線でオンプレとAzureを接続。インターネットを通らない。速く安定目的はオンプレとAzureの専用線。VNet間の通信保護ではない

通信の制御・保護

サービス一言ポイント
NSG受付係。通信を許可/拒否するルールの集合サブネットまたはNICに関連付ける(VNet自体には不可)。1つのNSGを複数のサブネット/NICで使い回せる。暗号化はしない
Azure FirewallNSGの上位互換のマネージドFW。複数VNet/サブスクをまたぐ集中管理、FQDNフィルタ、脅威インテリジェンスNSGでできることは全部できる。暗号化はしない
DDoS Protection大量アクセス(洪水攻撃)から守る。境界層の防御個別の通信の許可/拒否はしない
Azure BastionブラウザからTLSでVMにRDP/SSH。VMにパブリックIP不要安全なリモート接続
サービスエンドポイント / プライベートエンドポイントAzureのPaaSサービス(例: ストレージ)への安全な接続プライベートエンドポイントはVNet内のプライベートIPを付与する。サービスエンドポイントは付与しない

NSGのルールは5タプル(送信元IP/送信元ポート/宛先IP/宛先ポート/プロトコル)で書かれ、優先度は数字が小さい方が先に評価されます。

「制御」と「暗号化」は別の機能
NSGもAzure Firewallも、通す/止めるのフィルタで、暗号化はしません。暗号化が必要な場面では、SSL/TLSやVPN Gatewayを思い浮かべます。

負荷分散・トラフィック管理

サービスレイヤー一言
Azure Load BalancerL4(TCP/UDP)同一リージョン内で、VMへ負荷分散。インバウンドNATルール=特定ポートを特定の1台のVMに転送
Application GatewayL7(HTTP/HTTPS)URLパスなどで振り分け。WAF(Webアプリファイアウォール)付き
Azure Front DoorL7・グローバル世界規模のWeb配信・高速化
Traffic ManagerDNSベース複数リージョンへDNSで振り分け。通信を許可/拒否はしない
Azure DNS-ドメイン名の解決(DNSホスティング)

取り違えポイント

  • 「特定の1台のVMだけに転送」→ ロードバランサーのインバウンドNATルール(NSGのインバウンドルールは許可/拒否だけで、転送はしない)
  • 「インターネットからVMにHTTPでアクセスできるように」→ NSGとAzure Firewall(Traffic Managerは通信の許可/拒否とは無関係)
  • 「環境内のサーバー同士の通信制御」→ NSG/Firewall(VPN Gateway/ローカルネットワークゲートウェイはオンプレ接続用で無関係)

言えるようになること

  • ピアリングとグローバルピアリングを言い分けられる
  • VPN GatewayとExpressRouteの違いを言える
  • NSGの関連付け先と、暗号化しないことを言える
  • LoadBalancerとApplication Gatewayの違いを言える
