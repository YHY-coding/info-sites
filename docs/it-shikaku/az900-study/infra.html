3. Azureの物理インフラと階層構造(リージョン・ゾーン・SLA)

ドメイン2は試験で最大の配点で、最難関の範囲です。丸暗記ではなく「何をするためのサービスか(動詞)」で覚えます。まずは物理インフラからです。

リージョンとリージョンペア

  • リージョン: Azureがある街(地域)。複数のデータセンターの集まり。例: 東日本、西日本、米国東部
  • リージョンを選ぶ基準: ユーザーに近い(遅延が小さい)/法規制・データ所在地/提供サービスの有無/価格
  • リージョンペア: 同じ地域内の2つのリージョンがペア(数百km以上離れている)。災害時の復旧に備える。更新はペアの片方ずつ順番に行う。障害時はペアの一方の復旧が優先される

特殊リージョン

リージョンポイント
Azure Government米国政府機関向けの分離された環境。Microsoft自身が運営。米国籍の審査済み担当者のみアクセス可

「特殊リージョンはすべて外部委託」と一括りにしないでください。

可用性ゾーンと可用性セット

  • 可用性ゾーン: 同じリージョン内の、物理的に別々のデータセンター(電源・冷却・ネットワーク独立)。同じ街の別々のマンション棟。対応リージョンには最低3つのゾーンがある。VMを2つ以上の異なるゾーンに配置するとSLA 99.99%。データセンター単位の障害を防ぐ
  • 可用性セット: 同じデータセンターの中で、VMを障害ドメインと更新ドメインに分散する。同じ棟の中で別フロア・別系統に分けるイメージ。VMを2台以上でSLA 99.95%
  • 障害ドメイン: 電源・ネットワーク機器など物理インフラを共有する単位。最大3
  • 更新ドメイン: 計画メンテナンス時に同時に再起動される単位。最大20(既定5)
日常のたとえ
「電源・ネットワーク」の話が障害ドメイン、「メンテナンス再起動」の話が更新ドメインです。

99.99%に必要な最小VM台数・ゾーン数は2です(3ではありません)。1つのリージョンにゾーンは3つ用意されていますが、使うのは2つで足ります。「用意されている数」と「使う数」を混同していないか、毎回自問してください。

SLAは固定値ではありません。複数リージョン・ゾーン・可用性セットへの配置や、Premiumプランの利用で、より高いSLAを得られる場合があります。ただし、単にサブスクリプションを買い増すだけでは向上しません。

リソースの階層構造

管理グループ(複数サブスクをまとめて統制)
 └ サブスクリプション(請求・アクセス管理の境界)
    └ リソースグループ(同じ寿命のリソースの入れ物)
       └ リソース(VM、ストレージ等)
  • リソースグループ(RG): リソースの論理的な入れ物。リソースは必ず1つのRGに属する(同時に複数不可)。RGの入れ子はできない。RGを削除すると中のリソースも全て削除される
  • RGは、リソース間の通信可否とは無関係(通信を制御するのはVNetとNSG)。「RG内のリソースとしか接続できない」は誤りで、別RGのリソースとも接続できる
  • サブスクリプション: 請求とアクセス管理の境界。クォータ(上限)もここ。1つのAzureアカウントに複数持てる
  • 管理グループ: 複数のサブスクリプションにまたがって、ポリシーやアクセス権を一括適用(継承される)
  • 無料アカウントは、期間(30日)の経過かクレジットの使い切りで期限切れになる。最新の条件は公式で確認

Azure Resource Manager(ARM)

Azureの管理レイヤーです。Portal・CLI・PowerShell・REST APIのどこから操作しても、最終的にARMを通ります。ARMテンプレート(JSON)やBicepは、宣言型のIaCで、設計図を書けば同じ環境を何度でも再現(べき等)できます。

言えるようになること

  • リージョン・ゾーン・可用性セットの違いを、街・別の棟・同じ棟の別系統で言える
  • SLA 99.99%に必要な最小ゾーン数が2だと言える
  • 階層(管理グループ→サブスクリプション→RG→リソース)を言える
  • RGの3つの性質(1つだけ所属、入れ子不可、削除で中身も消える)を言える
