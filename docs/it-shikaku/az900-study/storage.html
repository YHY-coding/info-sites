6. ストレージとデータ移行(Blob・Files・冗長性)

世界観は「街の配送・共有スペース」です。ストレージアカウントの中に、4種類のサービスが入っています。

サービスたとえ何を保存キーワード
Blob Storage宅配ロッカー非構造化データ(画像・動画・バックアップ・ログ)をURL(HTTP)で取得オブジェクトストレージ。VMのディスクの実体も内部的にはBlob
Azure Files共有フォルダファイル共有。SMB(主にWindows)とNFS(主にLinux)両対応でネットワークドライブとしてマウント「ドライブとしてマップ」→Files
Table Storage電話帳NoSQLの構造化データ(キーと属性)スキーマレスのキー/属性ストア
Queue Storage伝言板メッセージのキュー。アプリ間の非同期メッセージング大量のメッセージを保存してコンポーネント間をつなぐ
Managed DisksVMのハードディスクVMのOSディスク/データディスク実体はBlob
FilesとBlobの区別
「ネットワークドライブとしてマップ/マウント」→ Files。「VMのディスクの保存先」や汎用のオブジェクト保存 → Blob。「FilesはSMBだけ」は不完全で、SMBとNFSの両方に対応しています。

冗長性(コピーをどこに持つか)

種類内容守れる範囲
LRS(ローカル冗長)1つのデータセンター内に3コピーディスク/ラック障害
ZRS(ゾーン冗長)3つの可用性ゾーンに分散データセンター障害
GRS(geo冗長)LRS+別リージョン(ペア)にもコピー(合計6)リージョン障害
GZRS(geoゾーン冗長)ZRS+別リージョンにもコピーゾーン+リージョン障害
RA-GRS / RA-GZRS上記+セカンダリを読み取り可能同上

アクセス層(Blob)

層用途コスト
ホット頻繁にアクセス保存は高い/アクセスは安い
クールたまに(30日以上保存)保存は安い/アクセスは高め
コールドめったに(90日以上)さらに安い
アーカイブほぼ使わない長期保存(180日以上)。オフラインで、使うにはリハイドレート(数時間)が必要最安/取り出しは遅い

課金の軸: ストレージは保存容量だけでなく、リクエスト数(読み書き回数)・データ転送・冗長性/アクセス層でも課金されます。「容量のみ課金」は誤りです。

データ移行ツール(「どれを使う?」の定番)

ツール一言
Azure Migrateオンプレのサーバー/DB/Webアプリのクラウド移行の評価と実行の統合ハブ
Azure Data Box物理デバイスを郵送してオフラインで大容量データ移行。回線を圧迫しない。「大容量・短期間・回線に影響なし」のシグナル
AzCopyコマンドラインでAzureストレージにデータコピー
Azure Storage ExplorerGUIでストレージを閲覧・操作
Azure File SyncオンプレのファイルサーバーとAzure Filesを継続的に同期(大量一括移行には向かない)

言えるようになること

  • 4つのストレージサービスを、ロッカー・共有フォルダ・電話帳・伝言板で言える
  • LRS・ZRS・GRS・GZRSの違いを、コピーの置き場所で言える
  • アクセス層の使い分けを言える
  • 移行ツールを、シグナル語で選べる
