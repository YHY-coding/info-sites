13. ひっかけパターンと似た者ペア(最優先の要注意10)

間違いは知識不足よりも、読み方の癖から生まれます。最優先で押さえる10項目と、似た者ペアの一覧です。1回正解しても定着とは見なさず、日を空けて2回連続で即答できて初めて「定着」です。

最優先の要注意10

ポイント型
A-1MFAは「異なるカテゴリ」を2つ。パスワード2つはNG。指紋認証はOK(その場で本人をスキャンして検証する)選択肢に同じ種類の要素が2つ並んでいたら、それだけでは成立しない
A-2Azure Policy と RBAC「モノ・場所」=条例(Policy)、「人」=鍵の配布係(RBAC)
A-3サブスクリプションの制限値(クォータ)を増やす「制限を増やす」「クォータ」→ 新しいサポートリクエスト
A-4Azure Files と Blob「ドライブとして使う」→ Files、「それ以外」→ Blob
A-5責任共有モデル。IaaS/PaaS/SaaSの境界はOS「管理負担を最小限に」→ PaaS。常に顧客責任: データ/デバイス/アカウント・ID
A-6可用性ゾーン/セットの数字「箱は3つ用意されているが、使うのは2つ」。障害ドメイン最大3、更新ドメイン最大20
A-7弾力性/拡張性/機敏性自動ドア=弾力性
A-8NSG / Azure Firewall は暗号化しない通す/止めるのフィルタ。暗号化はTLS、VPN Gatewayなど別機能
A-9Entra ID関連の動詞仕分け同期する→Entra Connect/見張る→Connect Health/攻撃者を探す→Defender for Identity
A-10認証と承認(認可)認証=誰か(身元)/承認=何ができるか(権限)。文の内容で判定する

「変更は必要ありません」形式の読み方

  • 下線部(「」の中)が正しければ、「変更は必要ありません」が正解。「変更が必要」と思い込む癖に注意する
  • 下線部が正しいか、まず自分で判定してから選択肢を見る

判定のフレーム(型)集

  1. IaaS/PaaS/SaaS: ①どの管理層か → ②その層は誰の担当か。軸はOS
  2. ネットワーク問題: ①何と何を繋ぐ/制御する話か → ②道具を選ぶ
  3. セキュリティ問題: ①多層防御のどの層か → ②その層の対策を選ぶ(「セキュリティ=MFA」と反射しない)
  4. コスト問題: ①見積(これから)/比較(移行)/実績(運用中)のどれか → ②ツールを選ぶ
  5. ガバナンス問題: ①モノか人か → ②Policy/RBAC。まとめる/分類する/守る/警告する → RG/タグ/ロック/予算
  6. 数字問題: SLA(99.9/99.95/99.99)、VM最小数(2)、障害ドメイン最大(3)、更新ドメイン最大(20)、VMSS最大(1000)。用意されている数と使う数を混同しない
  7. 限定的な言い切りに出会ったら、例外を疑う
