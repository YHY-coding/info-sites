2. ドメイン1:クラウドの概念(弾力性・責任共有モデル)

最初に学ぶ範囲で、点が取りやすい分野です。ただし「似た言葉の区別(弾力性/機敏性/拡張性)」と「責任共有モデル」で引っかかりやすい範囲でもあります。

クラウドの料金モデル

  • 従量課金(消費ベース): 使った分だけ請求。止めれば(基本的に)課金も止まる
  • CapEx(資本支出): 設備を先に買う。オンプレミスはこちら。OpEx(運用支出): 使った分を都度払う。クラウドはこちら
  • 注意: VMを停止(割り当て解除)しても、ディスクなどのストレージ料金は続く。放置したリソースにも課金される

クラウドのメリットの語彙

用語一言たとえ
高可用性止まりにくい。決められた稼働率を保つ予備の部屋・予備の棟がある
拡張性(スケーラビリティ)規模を増やせる(縮められる)こと。手動でも自動でもよい部屋を増やす
弾力性(エラスティシティ)負荷に応じて自動で増減できる。伸びる+縮む両方自動ドア(人が来れば開き、いなければ閉まる)
機敏性(アジリティ)要件の変化に素早く対応できる(スピード)引っ越し当日に部屋が手に入る
信頼性障害から回復して動作を続ける能力停電しても自家発電で動く
予測可能性性能とコストが予測できる水道料金の見通しが立つ
セキュリティ物理・ネットワーク・IDを守る仕組みがある警備つきマンション
ガバナンスルール・統制(ポリシー等)で管理できる街の条例
管理容易性管理しやすい(自動スケール、テンプレート、Portal/CLI)管理会社がやってくれる

弾力性・拡張性・機敏性の仕分け

  • 「自動で」「負荷に応じて」「伸びる/縮む」→ 弾力性。自動スケーリングは機敏性ではなく弾力性の例
  • 「規模を増減できる」(手動でもOK)→ 拡張性
  • 「すぐに」「迅速に」「新しい要件に素早く」→ 機敏性(スピードの軸)。不要になったサーバーをすぐ破棄できるのは機敏性の例
  • 弾力性は「増やす」だけでなく、「不要になったら解放(縮小)する」も含む

スケーリングの種類

  • 垂直スケーリング(スケールアップ/ダウン): 1台の性能を上げる/下げる。広い部屋に引っ越すイメージ
  • 水平スケーリング(スケールアウト/イン): 台数を増やす/減らす。同じ部屋を並べて増やすイメージ。需要増に合わせて自動で台数が増減するのは水平スケーリング(+弾力性)

クラウドモデル(デプロイモデル)

モデル説明たとえ
パブリッククラウドMicrosoftなど事業者が所有・運用。複数の顧客が共有基盤を使う(論理的には隔離)賃貸マンション街
プライベートクラウド自社専用。自社データセンター内で構築。自社が管理自分の家
ハイブリッドクラウドパブリックとプライベート(オンプレ)を連携して使う家と賃貸の両方を行き来
マルチクラウド複数の事業者(AzureとAWSなど)を使う複数の街に拠点

「既存のオンプレ資産を活かしつつクラウドも使う」はハイブリッドです。Azureには、オンプレや他クラウドのリソースをAzureから管理するAzure Arc、Azureの機能をオンプレで動かすAzure Local(旧Azure Stack HCI)があります。

サービスモデルと責任共有モデル

層オンプレIaaSPaaSSaaS
物理(ネットワーク・ストレージ・サーバー・仮想化)自社MicrosoftMicrosoftMicrosoft
OS自社自社MicrosoftMicrosoft
ミドルウェア・ランタイム自社自社MicrosoftMicrosoft
アプリケーション自社自社自社Microsoft
データ自社自社自社自社(データ自体の責任は常に顧客)
  • どのモデルでも常に顧客の責任: 情報とデータ、デバイス、アカウントとID
  • 常にMicrosoftの責任: 物理ホスト、物理ネットワーク、物理データセンター

判定の「型」

  1. どの管理層の話かを特定する(OS?アプリ?データ?物理?)
  2. その層が誰の担当かを、表で確認する
分類例
IaaSAzure Virtual Machines、Azure Virtual Network、Azure Storage(ディスク等)、ロードバランサー
PaaSAzure App Service、Azure SQL Database、Azure Cosmos DB、Azure Functions(サーバーレスでもある)、Azure Kubernetes Service(マネージド)
SaaSMicrosoft 365(Outlook・Teams)、Dynamics 365

Microsoft Entra IDのような境界的なサービスは、問題によって分類が異なることがあります。「自分でアプリを作る土台として使う=PaaS、完成品=SaaS」で判断し、迷ったら選択肢の中で最も近いものを選びます。

言い回しのシグナル

問題文のキーワード判定
「OSを管理」「OSにログインして」「事前に必要なソフトをサーバーにインストール」(婉曲表現)IaaS
「管理負担を最小限に」「Webアプリを動かしたい」「OSやパッチを意識したくない」PaaS
「マネージドデータベース」(Azure SQL、Cosmos DB)PaaS
「メール」「Office」「完成したソフトを使うだけ」SaaS
「PaaSはOSの完全な制御を提供する」誤り(OSの完全制御はIaaS)

サーバーレスと災害対策

  • サーバーレス: サーバーはもちろんあるが、利用者は存在を意識せず、コードだけ書けばよい。Azure Functions(イベント発生時にコードを実行)、Azure Logic Apps(ノーコード/ローコードのワークフロー)。実行された分だけ課金、自動でスケール。たとえ: タクシー
  • 高可用性: 止まらない(または止まっても短い)ように冗長化すること
  • 災害復旧: 大災害でサイトが全滅しても別の場所で復旧できる仕組み。Azure Site Recoveryが代表
  • 別の棟(ゾーン)や別の街(リージョン)に分散配置すると、より高い稼働率が得られる

言えるようになること

  • クラウドの料金モデル(OpEx)を言える
  • 弾力性・拡張性・機敏性を、キーワードで仕分けられる
  • 責任共有モデルの表を、OSを軸に読める
  • 常に顧客の責任である3つを言える
