12. 監視・SLA・サポートプラン

監視ツール(「見張る」だけで「防ぐ・治す」はしない)

サービス何を見る/知らせる一言
Azure Monitorメトリックとログの収集・分析・アラート。リソースの稼働状況・パフォーマンス何が起きているかの目
Log AnalyticsMonitorが集めたログをクエリ(KQL)で分析ログの検索窓口
Application Insightsアプリのパフォーマンス・可用性・例外の監視アプリ専用の診断
Azure Service HealthAzureのサービス障害・計画メンテナンス・勧告のうち、自分のサブスク/リージョンに影響するものを通知自分に関係のあるAzure側の問題
Azure status(ステータスページ)Azure全体の障害状況(個別化されていない公開ページ)全体掲示板
Resource Health個々のリソース(例: このVM)の正常性個別のカルテ
Azure Advisorベストプラクティスに基づく推奨事項を提示相談役(提案するだけ)

Azure Advisorの推奨は、信頼性・セキュリティ・パフォーマンス・コスト・オペレーショナルエクセレンスの5カテゴリです。5カテゴリに当てはまらないもの(例: Entra IDのユーザー設定の推奨)は対象外で、設定手順そのものを教える機能でもありません。

監視系サービスの鉄則
選択肢に「〜を防ぐ」「〜を防止する」「構成方法を教える」とあったら、監視系サービスの説明としては誤りの可能性が高いです。監視系は「知らせる・見せる・提案する」までです。

SLA(稼働率の約束)

  • 99.9%(スリーナイン)=年間ダウンタイム約8.8時間、99.99%=約52分
  • 複合SLA: 複数のサービスを組み合わせると、全体のSLAは個々のSLAの掛け算になり、個々より低くなる(直列でつながるため)。冗長化(並列)すると高くなる
  • SLAが守られなかった場合は、サービスクレジット(返金的な補償)
  • 無料のサービス/プレビューの機能には、通常SLAがない

サポートプラン

プランポイント
Basic全員に無料。課金・サブスクリプション管理の問い合わせのみ(技術サポートなし)。サードパーティソフトのサポートは対象外(Basicだけ)
Developer非本番向け。メールで技術サポート
Standard本番向け。24時間365日の技術サポート
Professional Direct重要システム向け。より迅速な対応・担当エンジニア
Unified/Premier大企業向け上位プラン
クォータ(制限値)を引き上げたいとき
新しいサポートリクエストを作成します。プランのアップグレードではありません(Basicでも依頼できます)。Policyの変更やサブスクリプション統合でも解決しません。「制限を増やす」「クォータ」という言葉を見たら、機械的に「新しいサポートリクエスト」を選びます。

サービスのライフサイクル

  • プレビュー: 先行公開版。パブリックプレビューは誰でも使える。プライベートプレビューは招待制。プレビューには通常SLAがない
  • 一般提供(GA): 正式提供。SLAの対象
  • Azure Marketplace: サードパーティのソフト・サービスを探して購入・デプロイできる市場
