8. ID・アクセス・セキュリティ(Entra ID・MFA・ゼロトラスト)

認証と承認

  • 認証(Authentication): 誰か(身元)の確認
  • 承認(Authorization): 何ができるか(権限)の判定。RBACは承認を実現する仕組み
  • 問題文に「認可」とあって選択肢に「承認」があるのは、同じ意味。単語の見た目に引っ張られず、文が「身元」の話か「権限」の話かで判定する
  • フェデレーション: 複数の組織/ID基盤の間で信頼関係を結び、1つの認証で複数のサービスを使えるようにする

Microsoft Entra ID(旧Azure Active Directory)

  • クラウドのID管理サービス。ユーザー・グループ・アプリの認証基盤
  • SSO(シングルサインオン): 1回のサインインで複数アプリを利用
  • ライセンス: Free / P1 / P2。P1=条件付きアクセス等、P2=Identity Protection・PIM
  • Microsoft Entra Domain Services: クラウド上のマネージドなAD DS(ドメイン参加等のレガシー機能)
  • 外部ID: B2B=パートナー企業のユーザーを招待、B2C=顧客向けのアプリ認証

多要素認証(MFA)と認証方法(最重要の引っかけ)

  • 3つのカテゴリ: 知っているもの(パスワード・PIN)/持っているもの(スマホ・セキュリティキー)/自分自身(指紋・顔)
  • MFAは、異なるカテゴリを2つ以上組み合わせること
  • NG: パスワード2つは同じカテゴリなのでMFAではない。写真付き身分証明書+パスポート番号など、同じカテゴリの繰り返しもNG
  • OK: パスワード+スマホアプリの承認、パスワード+指紋
  • パスワードレス: Windows Hello、FIDO2セキュリティキー、Microsoft Authenticatorアプリ
  • 条件付きアクセス: 「もし〜なら、〜を要求/ブロック」(場所・デバイス・リスクに応じてMFA要求など)。Entra ID P1以上

ゼロトラスト

「決して信頼せず、常に検証する」。社内ネットワークだからOK、とはしません。3原則は、①明示的に検証する、②最小特権アクセスを使用する、③侵害を想定する、です。「ネットワーク境界にファイアウォールを設置する」は旧来の境界型の考え方で、ゼロトラストの原則ではありません。

多層防御(城の7つのリング)

  1. 物理セキュリティ(データセンターの警備・入退室)
  2. IDとアクセス(MFA、条件付きアクセス、SSO)
  3. 境界(DDoS Protection)
  4. ネットワーク(NSG、ファイアウォール、セグメント化)
  5. コンピューティング(VMへのパッチ適用、エンドポイント保護)
  6. アプリケーション(安全なコード、脆弱性対策)
  7. データ(暗号化、Key Vault、アクセス制御)

「セキュリティ」と聞いて反射でMFAを選ばず、先に「どの層の話か」を特定します。
