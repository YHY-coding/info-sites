RDSの機能(マルチAZ・リードレプリカ)

一言で言うと
RDSは管理型のリレーショナルデータベース。可用性を高めるマルチAZと、読み取りを分散するリードレプリカは、目的が違う。

たとえ話

マルチAZは、本番機が壊れたときに交代する「待機の控え役」。リードレプリカは、問い合わせ対応を手伝う「応援役」。

押さえること

  • マルチAZ: 別のアベイラビリティゾーンにスタンバイを持ち、障害時に切り替える。主目的は可用性
  • リードレプリカ: 読み取り専用の複製。読み取り負荷を分散するのが主目的
  • 自動バックアップやパッチ適用などの運用作業を、AWS側が肩代わりしてくれる
  • 対応するデータベースエンジンの種類や、機能の細かな条件は、公式で確認
  • 物理的なサーバーのOSレベルの管理は利用者の責任ではなく、AWSの責任範囲

試験でのポイント

  • 「障害時の自動切り替え」→ マルチAZ
  • 「読み取りの負荷分散」→ リードレプリカ
