Auto Scalingの考え方

一言で言うと
Auto Scalingは、負荷に合わせてEC2インスタンスの数を自動で増減させる仕組み。必要なときに増やし、不要なときに減らす。

たとえ話

お客さんが増えたらレジを開け、減ったら閉めることで、待ち時間と人件費の両方を調整する店のようなもの。

押さえること

  • Auto Scalingグループで、最小数・希望数・最大数を設定して、台数の範囲を決める
  • 起動テンプレートで、どんなインスタンスを起動するか(AMI、タイプなど)を定める
  • スケーリングの方法には、指標に応じて増減させる方法や、時間帯で決める方法などがある。具体的な設定は公式で確認
  • ヘルスチェックで異常なインスタンスを見つけたら、置き換えて台数を保てる
  • ロードバランサーと組み合わせると、増減したインスタンスへ通信を振り分けられる

試験でのポイント

  • 「負荷に応じて台数を自動増減」→ Auto Scaling
  • 「異常なインスタンスの置き換え」→ Auto Scalingのヘルスチェック
  • 「台数が増えても通信を振り分ける」→ ELBと併用
