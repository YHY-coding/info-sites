Lambdaの料金と制限(概要)

一言で言うと
AWS Lambdaは、サーバーを管理せずにコードを実行できるサービス。料金は、実行された分に応じて決まる従量課金が基本で、実行時間やメモリなどに制限がある。

たとえ話

Lambdaは、必要なときだけ呼ぶ出張料理人のようなもの。呼ばれて料理した分だけ支払えばよく、厨房を常に借りておく必要はない。ただし、一度に作れる量や時間には決まりがある。

押さえること

  • Lambdaは、イベント(ファイルの保存、リクエストの到着、予定時刻など)をきっかけに、関数(コード)を実行する
  • サーバーのプロビジョニングや管理は不要。実行環境の運用はAWSが担当する(責任共有モデルでの整理は公式で確認)
  • 料金は、主に「リクエストの回数」と「実行時間(割り当てたメモリ量との組合せ)」で決まる。具体的な単価は公式で確認
  • コードが動いていない間は、実行にかかる料金は基本的に発生しない
  • 1回の実行時間には上限がある。そのため、長時間かかる処理には向かない場合がある。具体的な上限値は公式で確認
  • 割り当てるメモリ量などにも上限・設定幅がある。数値は変わりうるため、公式で確認
  • 短い処理やイベント駆動の処理に向き、常時動かし続けるサーバー型の処理や、長時間の処理にはEC2やコンテナの方が合う場合がある

試験でのポイント

  • 「サーバー管理不要」「実行した分だけ課金」=Lambda、と結びつける
  • 実行時間に上限があるため、長時間の処理には向かない場合がある、という点を押さえる
