SQS・SNS・EventBridgeの使い分け

一言で言うと
SQSは「届いたメッセージを溜めて取りに来てもらう」キュー、SNSは「購読者全員に一斉に届ける」通知、EventBridgeは「イベントを条件で仕分けて宛先へ送る」仕組み。

たとえ話

SQSは、順番待ちの受付ボックス。SNSは、同じお知らせを登録者全員に配る一斉メール。EventBridgeは、届いた手紙を宛名の条件で仕分けして、担当の部署に回す仕分け係。

押さえること

  • SQS(Simple Queue Service)は、メッセージを一時的に溜めるキューのサービス。送る側と受ける側を切り離し、処理が追いつかない間も溜めておける
  • SQSでは、受け取る側が自分のペースでメッセージを取りに行く(プル型)。処理の平準化や、障害時の取りこぼし防止に役立つ
  • SNS(Simple Notification Service)は、発行したメッセージを、購読している複数の宛先に一斉に届けるサービス(プッシュ型)。宛先にはメール、SQS、Lambdaなどがある
  • SNSのトピックに複数のSQSキューを購読させ、一つのメッセージを複数の処理に振り分ける構成(ファンアウト)がよく使われる
  • EventBridgeは、AWSサービスやアプリで起きたイベントを、ルールの条件に応じて、Lambdaなどの宛先に送る。スケジュールによる実行もできる
  • 三者は、システム同士の結合をゆるくして、片方の障害や負荷が全体に波及しにくくする「疎結合」の部品として使われる
  • 細かな機能(キューの種類、料金、上限値)は、公式で確認

試験でのポイント

  • 溜めて取りに来る=SQS、全員に一斉配信=SNS、条件で仕分け=EventBridge、と結びつける
  • 疎結合な設計の部品として、この3つが挙がることを押さえる
