3. 権限とIDの超基礎(入館証にたとえる)

「誰なのか」と「何ができるのか」は、別々に管理されます。

日常のたとえ
会社の入館証です。社員証は「あなたが誰か」を表します。そのうえで、「どのフロアのどの部屋に入れるか」は、別の権限カードで決まります。
言葉意味たとえ
Microsoft Entra ID誰が使ってよいかを管理する仕組み(旧Azure AD)会社全体の入退館システム
ユーザーAzureを使う1人ひとりのアカウント社員証を持つ本人
グループユーザーをまとめた名簿。名簿に権限を付けると、載っている全員に効く部署の名簿
ロール「何ができるか」をまとめたセット権限カードの種類
スコープ権限が及ぶ範囲。サブスクリプション、リソースグループ、リソースのどこに付けるかビル全体か、フロアか、部屋か
RBAC「誰に」「どのロールを」「どの範囲で」与えるかを決める仕組み建物側の鍵の管理
最小権限の原則必要な作業ができる、いちばん弱い権限だけを与えること必要な部屋の鍵だけ渡す

基本の4つのロール

ロールできること
所有者すべてのリソースの管理と、ロールの割り当て変更まで
共同作成者すべてのリソースの管理。ただしロールの割り当て変更はできない
閲覧者読み取りだけ
ユーザーアクセス管理者ロールの割り当て(誰に何を許すか)の管理だけ。リソース自体は管理できない

ロール名を読むときは、後ろの役職の部分(所有者・共同作成者・閲覧者・オペレーターなど)が、権限の強さを決めます。たとえば「オペレーター」は、すでにあるものを操作する係で、新しく作る係ではありません。

権限カードは、2種類ある

ここが一番大切です。Azureには、権限のシステムが2つ、別々にあります。

Azure RBACEntraディレクトリロール
管理する対象Azureのリソース(VM・ストレージ・ネットワークなど)ユーザー・グループ・デバイスなど、人や組織の情報
たとえ建物側の鍵総務部・人事部のスタッフ証
代表例所有者・共同作成者・閲覧者全体管理者・ユーザー管理者

2つは別のシステムです。「〇〇管理者」という見慣れない名前が出てきたら、まず「リソースを操作する権限か、社員名簿を管理する権限か」を考えます。

言えるようになること

  • ユーザー・グループ・ロールの違いを、入館証のたとえで言える
  • 所有者・共同作成者・閲覧者の違いを言える
  • 最小権限の原則を、一言で言える
  • Azure RBACとEntraディレクトリロールが別のシステムだと言える
