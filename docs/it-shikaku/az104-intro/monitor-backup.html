7. 監視とバックアップ編(警備センターと引っ越し業者)

監視は「異常に気づく仕組み」、バックアップは「壊れても元に戻せる仕組み」です。監視は「会社の監視カメラと警備センター」、バックアップは「引っ越し業者と保管倉庫」にたとえます。

監視(警備センター)

Azure Monitorは、Azureの状態を集めて、見て、異常を知らせる仕組みです。会社中のカメラとセンサーを、警備センターに集めるイメージです。

たとえ実際の用語
警備センター全体Azure Monitor
センサーが記録する数値(温度計)メトリック。CPU使用率など、数字で測ったもの
出来事の記録帳ログ。「何が起きたか」の記録
記録保管室と分析デスクLog Analyticsワークスペース。ログをしまい、検索できる場所
記録保管室での調べ方KQL。Log Analyticsで検索するための専用の言葉
建物全体の入退室記録アクティビティログ。「誰が・いつ・何をしたか」という操作の履歴。自動で記録される
「こうなったら異常」という警報ルールアラートルール
警報が鳴ったときの緊急連絡網アクショングループ

診断設定の送信先は、役割で選びます

診断設定は、リソースが出すログを、どこへ送るかを決める設定です。

送信先役割たとえ
Log Analyticsワークスペース分析する専門の司書がいる記録保管室
ストレージアカウント安く長く保管する。分析はできないそのまま保管する倉庫
イベントハブ他のシステムへ転送する。分析はできない別の宛先へ流す配送センター

「ログを分析したい」と書いてあれば、答えはLog Analyticsワークスペースです。保管ならストレージ、転送ならイベントハブ、と覚えます。

アラートの数え方

  • アラートルールは、基本的に1つのルールにつき、1つのシグナル(監視する項目)。メトリック同士なら、1つのルールにまとめられる。ただし、通知先が違うなら、ルールは分ける
  • アクショングループは、通知先の組み合わせのパターンの数だけ必要。同じ組み合わせなら、使い回せる
例
3つの監視項目があり、通知先が「田中さんと佐藤さん」「田中さんと佐藤さん」「田中さんだけ」だとします。アクショングループの最小数は2です。最初の2つは同じ組み合わせなので、1つを共用できます。

Network Watcherはネットワークの診断キットです。「いま、この通信が通る設定になっているか」を、その場で1回だけ確認するのが「IPフロー検証」です。時間をかけて継続的に見るなら「接続モニター」です。

バックアップ(引っ越し業者と保管倉庫)

  • 客 = あなた(管理者自身)。VMではない
  • 荷物 = VMのデータ
  • 倉庫 = Recovery Servicesコンテナー
  • 引っ越し業者 = Azure Backupの仕組み
  • 契約プラン = バックアップポリシー

Recovery Servicesコンテナーは、中にバックアップデータが残っている間は、削除できません。削除の順番は、決まっています。

  1. バックアップを停止する
  2. バックアップデータを削除する
  3. コンテナーを削除する

ポータルでも、バックアップを停止するまでは、「バックアップデータの削除」のボタンが押せません。

日常のたとえ
倉庫を解体するには、まず荷物を運び込み続けているベルトコンベアを止めます。次に積まれた荷物を運び出し、最後に空っぽになった倉庫を解体します。

言えるようになること

  • メトリックとログの違いを、温度計と記録帳で言える
  • 診断設定の送信先を、分析・保管・転送で言い分けられる
  • アラートルールとアクショングループの数え方を言える
  • Recovery Servicesコンテナーを削除する順番を言える
