4. ネットワーク編(マンションにたとえる)

Azureのネットワークは、「敷地を作り、区画に分け、門番と通り道を決める」という流れで組み立てます。この章では、ネットワークを「マンション」にたとえます。

  • 仮想ネットワーク(VNet)= マンション全体
  • サブネット = フロア
  • VM = フロアにある部屋
  • NSG = フロアの入口に立つ警備員
  • ピアリング = 棟と棟をつなぐ渡り廊下
  • ルートテーブル = そのフロア専用の外出ルールの貼り紙

仮想ネットワーク(VNet)とサブネット

VNetは、Azureの中に作る、自分専用のネットワークです。VNetの中を、サブネットという区画に分けて使います。同じVNetの中のVM同士は、何も設定しなくても通信できます。

NSG(フロアの警備員)

NSGは、「この通信は通す、この通信は止める」というルールを、一覧にしたものです。サブネットか、NIC(VMがネットワークにつながる接続口)に関連付けます。

  • 1つのルールは、優先度・ソース(送信元)・宛先・ポート・許可か拒否か、で書かれる
  • 優先度の数字が小さいルールから順に見て、最初に当てはまったもので決まる。それより後ろのルールは見ない
  • 入ってくる通信(受信)と、出ていく通信(送信)は、別々のルールで見る
  • 最初から入っている既定のルールがある。たとえば、同じVNet内の通信は許可される
  • ソースや宛先には、特別な名前が書ける。Internetはインターネット、VirtualNetworkは同じVNet内、StorageはAzureのストレージサービスをまとめた名前
  • NSGは、関連付けた対象(サブネットかNIC)にしか効かない
例
あるNSGに「ソースがInternet、宛先がVM1、443番、拒否」というルールがある。同じVNet内のVM2から、VM1の443番へ接続できるでしょうか。答えは「できる」です。拒否されるのはソースがInternetの通信だけで、VNet内のVM2は対象外だからです。ルールの名前ではなく、ソースの欄を読むのがコツです。
日常のたとえ
警備員は、手元のチェックリストを一番上から確認します。最初に当てはまった行の通りに動き、残りは見ません。1階の入口にいる警備員は、2階の出入りを見ません。

ピアリング

ピアリングは、別々のVNetをつないで、行き来できるようにする設定です。つないだ相手としか通信できません。VNet1とVNet2、VNet1とVNet3がつながっていても、VNet2とVNet3は自動ではつながりません。

日常のたとえ
A棟とB棟、A棟とC棟に渡り廊下があっても、B棟からC棟へは行けません。A棟が仲介役になってくれることもありません。

ルートテーブル

Azureは、通信の通り道を自動で決めます。ルートテーブルを使うと、「この宛先への通信は、必ずこの中継役のVMを通す」と指定できます。

  • ルートテーブルは、適用したサブネットから出ていく通信にだけ効く
  • 中継役のVMには、ルーティングを有効にする設定と、NICのIP転送を有効にする設定の、両方が必要
  • 行きと帰りで通り道が違っても、中継役が正しく動いていれば、接続はできる

ロードバランサー(電話交換システム)

ロードバランサー(負荷分散装置)は、たくさんのアクセスを、複数のVMに振り分ける装置です。会社の代表電話にかかってきた電話を、空いている担当者につなぐ電話交換システムにたとえられます。

部品意味たとえ
フロントエンドIPお客さんがかける接続先のIP代表電話番号
バックエンドプール振り分け先のVMの名簿担当者の名簿
正常性プローブVMが生きているかを定期的に確認する仕組み担当者が席にいるかの確認
負荷分散規則「何番で受けて、どの番号に渡すか」の対応受付のルール
  • 負荷分散規則を作るときの必須パーツは、バックエンドプールと正常性プローブの2つだけ
  • ロードバランサーとパブリックIPは、SKU(種類)を同じにそろえる。現行はStandardで、Basicは廃止された。StandardのパブリックIPは、静的(固定)のみ
  • パブリックのロードバランサーはインターネットから、内部のロードバランサーはVNetの中から使う

言えるようになること

  • VNet・サブネット・NSG・ピアリング・ルートテーブルの役割を、マンションのたとえで言える
  • NSGのルールを、優先度の小さい順に読み、ソースの欄まで確認できる
  • ピアリングが、直接つないだ相手としか通信できないと言える
  • ロードバランサーの4つの部品と、必須の2つを言える
