5. 監視・バックアップ(警備センター・引っ越し業者と保管倉庫)

監視は「何を・どこへ送り・何を使って分析し・誰に知らせるか」の4つに分けて考えると、選択肢が機械的に絞れます。

たとえ実際の用語
監視カメラ・センサー網と警備センター全体Azure Monitor
センサーの設置場所(監視対象)データソース
センサーが記録する数値(温度計)メトリック
出来事の記録帳ログ
記録保管室と分析デスクLog Analyticsワークスペース
記録保管室での調べ方KQL(Kusto Query Language)
「こうなったら異常」という警報ルールアラートルール
実際に鳴った警報アラート
警報が鳴ったときの緊急連絡網アクショングループ
「この時間帯は警報を鳴らさない」スケジュール表アラート処理ルール

データの種類と保存期間

種類収集保存期間
メトリック(数値)自動93日
ログ(出来事の記録)Log Analyticsワークスペースへの手動設定が必要30〜730日で調整
アクティビティログ(サブスクリプション全体の操作履歴)自動90日

診断設定の送信先は、役割で選ぶ

送信先役割分析(クエリ)
Log Analyticsワークスペース分析用の保存先。KQLで検索・分析できるできる
ストレージアカウント安価な長期アーカイブできない
イベントハブ他のシステムへのリアルタイム転送できない
パートナーソリューションDatadogなど外部サービスと連携外部サービス側

覚え方: ストレージ=保管、イベントハブ=転送、Log Analytics=分析。「分析」という言葉が出たら、機械的にLog Analyticsワークスペースを選びます。

日常のたとえ
ストレージは「そのまま保管する倉庫」、イベントハブは「別の宛先へ流す配送センター」、Log Analyticsは「専門の司書が検索に応えてくれる記録保管室」です。

アラートルールとアクショングループ

アラートルールは、スコープ(対象リソース)、シグナル、条件(しきい値)の3点セットです。アラートは、シグナルによって、メトリックアラート、ログ検索アラート、アクティビティログアラートの3種類に決まります。アクショングループは、鳴ったあとに「誰に・どうやって知らせるか」を決める部品です。通知手段はメール・SMS・音声通話で、Azure Function・ロジックアプリ・Azure Automationを呼び出すこともできます。

数を数えるルール

  • アラートルールは、基本1つにつき1つのシグナル。例外として、メトリック同士なら1つのルールに複数の条件を入れられる。ただし、通知先(アクショングループ)が違うなら、ルールは分ける
  • アクショングループは、通知先の組み合わせのパターン数だけ必要。同じ組み合わせの通知先は、複数のルールで使い回せる
  • ユーザーの所属グループ(Entra側の分類)は、アクショングループとは無関係
日常のたとえ
アラートルールは「見回りの指示書」、アクショングループは「指示書に書く連絡先リスト」です。指示書は4枚必要でも、同じ連絡先リストは使い回せるので3枚で足りることがあります。
  • VMに変更があったらメールで知らせたい場合は、アクティビティログを条件にしたアラートルールを作り、通知手段としてアクショングループを指定する。この順番を取り違えない
  • アラート処理ルールで「通知を表示しない」を選ぶと、アラート自体は発生するが、アクショングループが呼ばれず通知は届かない。特定の時刻や定期的なスケジュールにできる
  • アラートの「ユーザーの応答」(新規・確認済み・終了)は、どの状態からでも、他の2つに自由に変更できる
  • 診断設定で収集するリソースログは手動設定が必要。アクティビティログは自動で記録される

機能用途特徴

NSGを設定したあとの疎通確認は、IPフロー検証です。時間の経過で見たいなら接続モニターを使います。未接続のディスクを見つけるには、Azure Advisorの推奨事項が使えます(30日を超えてVMに接続されていないディスクを自動で検出)。

Azure Backup(引っ越し業者と保管倉庫)

  • 客 = あなた(管理者自身)。VMではない
  • 荷物 = VMのデータ
  • 倉庫 = Recovery Servicesコンテナー
  • 引っ越し業者 = Azure Backupの仕組み
  • 契約プラン = バックアップポリシー

Recovery Servicesコンテナーは、バックアップデータが残っている間は削除できません。削除の順番は、バックアップの停止、バックアップデータの削除、コンテナーの削除です。「バックアップデータの削除」ボタンは、バックアップを停止するまで押せません。ポータルのボタンの有効・無効が、順番の依存関係をそのまま表しています。

誤りの選択肢の例: VMの電源を止める(削除手順と無関係)、バックアップポリシーを削除する(溜まったデータは消えない)。

日常のたとえ
倉庫を解体するには、まず荷物を運び込み続けているベルトコンベアを止めます。次に積まれた荷物を運び出し、最後に空の倉庫を解体します。
